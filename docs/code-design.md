# 代码设计

## 两进程与分层

发送端和接收端是独立进程，各自通过本机 UDP loopback 交换字节。UDP 只承载完整的教学帧；程序在用户态写入并解析模拟的 Ethernet II、IPv4 和 TCP 头。这样两边都能看到同一帧的发出封装与收到解包。

```text
发送端进程                                  接收端进程
应用消息 -> TCP头 -> IPv4头 -> Ethernet帧 --UDP--> 解析 Ethernet
   ^                                               -> 解析 IPv4
   +------------------- 回复帧 <------------------ -> 解析 TCP -> 应用消息
```

MAC 地址和 IP 地址是演示用的逻辑地址（客户端 `10.0.0.1`，服务端 `10.0.0.2`），不会配置到网卡。操作系统只看到两个进程之间的 UDP loopback 数据报，不会把里面的合成 TCP 头当成真正 TCP 流量。

## 状态和报文顺序

连接阶段固定使用初始序号：客户端 `1000`，服务端 `7000`。

| 步骤 | 方向 | TCP 标志 | 示例 Seq/Ack | 状态含义 |
|---|---|---|---|---|
| 1 | 客户端 → 服务端 | SYN | `1000 / 0` | 客户端请求连接；SYN 消耗一个序号 |
| 2 | 服务端 → 客户端 | SYN, ACK | `7000 / 1001` | 服务端确认客户端 SYN，并发送自己的 SYN |
| 3 | 客户端 → 服务端 | ACK | `1001 / 7001` | 客户端确认服务端 SYN；连接建立 |
| 4 | 客户端 → 服务端 | PSH, ACK | `1001 / 7001` + 消息 | 发送应用数据 |
| 5 | 服务端 → 客户端 | ACK | `7001 / 1001+消息字节数` | 累计确认客户端数据 |
| 6 | 服务端 → 客户端 | PSH, ACK | 服务端序号 + 回复 | 发送应用层回复 |
| 7 | 客户端 → 服务端 | ACK | 确认服务端回复的下一个字节 | 确认全部回复内容 |

例如消息 `hello receiver` 是 14 字节，从 Seq `1001` 开始，服务端返回 Ack `1015`。TCP 序号以字节为单位；SYN 和 FIN 各消耗一个序号。

首次请求/回复完成后，双方进入聊天循环。任一端输入一行，就发送一个 PSH+ACK 数据段；对端验证序号、增加接收字节计数并发送 ACK。每次收发都会刷新空闲计时器。用户输入 `:quit` 时可由任一端发起关闭；无人输入且超时到达时由服务端发起关闭：

```text
服务端 FIN,ACK -> 客户端 ACK -> 客户端 FIN,ACK -> 服务端 ACK
   第一次挥手       第二次挥手       第三次挥手       第四次挥手
```

两个方向分别结束，所以 FIN/ACK 使用各自方向的序号。该教学状态机只走这条正常路径；超时或序号不符时程序报错结束，不执行 TCP 标准中的重传与恢复。

## 字段编码与解析

- `build_packet` 按大端序写入 14 字节 Ethernet II、20 字节 IPv4、20 字节 TCP，再附加载荷。
- IPv4 Protocol 为 `6`，TCP 头部数据偏移为 5（20 字节，无 TCP 选项）。
- IPv4 校验和覆盖 IP 头；TCP 校验和覆盖 IPv4 伪首部以及 TCP 头和载荷。接收解析器显示校验和结果。
- `inspect_packet` 按 Ethernet EtherType、IPv4 Protocol 和 TCP 数据偏移逐层确定下一层位置；在读取字段前检查输入长度。
- `send_packet` 每次先打印构造帧的逐层解析，再用 `sendto` 传给另一进程；`receive_packet` 从 socket 收到完整 UDP 载荷后打印逐层解包。`run_chat` 同时轮询终端输入和 UDP socket，让两端都能发消息。

示例运行中，14 字节的 `hello receiver` 产生 68 字节 Ethernet 帧：14 字节 Ethernet + 20 字节 IPv4 + 20 字节 TCP + 14 字节数据。响应和控制报文长度随其载荷变化。

## 教学范围

这个项目演示帧格式、校验和、TCP 序号确认、持续双向数据和连接状态变化。它不是完整 TCP/IP 实现：没有重传、拥塞控制、滑动窗口流控、多连接复用、乱序处理、分片重组或真实内核抓包。要研究真实内核生成的握手报文，应使用 Wireshark/tcpdump 等工具观察真正的 TCP socket 流量。
