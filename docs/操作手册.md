# 操作手册

## 1. 编译

需要支持 C11 的编译器和 Make。在项目根目录执行：

```sh
make
```

## 2. 启动两个终端

在终端 A 启动接收端，参数依次为角色、UDP 端口、空闲超时秒数：

```sh
./build/packet_demo receive 9000 5
```

看到“监听”日志后，在终端 B 启动发送端：

```sh
./build/packet_demo send 127.0.0.1 9000 5 "你好，接收方"
```

参数依次为角色、接收端 IPv4 地址、端口、空闲秒数和消息内容。省略参数时，默认地址为 `127.0.0.1`、端口为 `9000`、超时为 `5` 秒，默认消息为“你好，接收方！”。接收端会自动回复一条包含收到内容的消息。

也可以在两边分别运行 `make receiver` 和 `make sender` 使用默认参数；先运行 `make` 编译后再启动两个角色。`make run` 显示完整命令用法。

## 3. 观察连接过程

两边日志会各自显示发出的 TCP 教学帧（`TX 封装`）和收到的帧（`RX 解包`）。每帧都打印 Ethernet、IPv4、TCP 字段、校验和；有载荷时还会展示应用消息。

按时间顺序观察：

1. **三次握手**：客户端 `SYN` → 服务端 `SYN ACK` → 客户端 `ACK`。日志状态从 `CLOSED/SYN-SENT` 到 `SYN-RECEIVED`、`ESTABLISHED`。
2. **请求与确认**：客户端发送 `PSH ACK` 和消息；服务端按载荷字节数增加确认号并发送 `ACK`。
3. **服务端回复**：服务端发送 `PSH ACK` 和回复；客户端确认回复中所有字节。
4. **空闲超时**：服务端在收妥客户端对回复的 ACK 后开始计时。到达设置的秒数仍没有新帧时，服务端主动发送 `FIN ACK`。
5. **四次挥手**：服务端 `FIN` → 客户端 `ACK` → 客户端 `FIN` → 服务端 `ACK`。两端最后显示连接关闭。

## 4. 调整参数

把 `9000` 换成未被占用的本机端口；两端端口必须相同。把超时改为 `1` 到 `120` 秒之间的整数，两端也应使用相同值。修改消息文本可观察载荷长度、序号和累计确认号的变化；消息限制为 500 字节。

发送端必须在接收端开始监听后启动。运行结束后可在同一终端重新启动接收端，再运行新的发送端。

## 5. 理解日志中的序号

示例客户端初始序号是 `1000`，SYN 消耗一个序号，所以服务端确认 `1001`。如果客户端消息有 14 个字节，数据从 `Seq=1001` 开始，服务端累计确认 `Ack=1015`，含义是下一个期望字节是 1015。TCP 序号按字节计数；SYN 和 FIN 各自也占用一个序号。

## 6. 范围说明与故障排查

- Ethernet MAC、IPv4 地址是程序虚构的逻辑字段。整帧作为 UDP 数据报在 `127.0.0.1` 上传递；实际网卡和操作系统 TCP 栈不会看到这些自构造头部。
- 本示例不模拟重传、拥塞控制、乱序重组、IP 分片、TCP 选项或多条并发连接。
- 若发送端提示超时，确认接收端先启动、两侧端口相同且本机允许 loopback UDP。
- 如果 `bind` 提示地址已占用，换一个端口并在发送端同步修改。
- 要观察真实操作系统 TCP 报文，可另用 Wireshark 或系统抓包工具抓取真实 TCP socket 流量；这和本示例的用户态状态机是两个不同的观察对象。

清理二进制：

```sh
make clean
```
