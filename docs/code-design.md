# 代码设计

## 处理流程

程序展示接收方向的分层处理：

```text
build_packet
  └─ 在 packet 字节数组中依次写入 Ethernet、IPv4、TCP、HTTP
       └─ main 将同一数组交给 parse_packet
            ├─ 检查 Ethernet 长度和 EtherType
            ├─ 检查 IPv4 版本、头长、总长、分片与协议号
            ├─ 检查 TCP 头长并解析 TCP 字段
            └─ 展示 TCP 载荷
```

这是用户态的学习模拟。真实系统中，网卡驱动把收到的帧交给内核网络栈；本程序用一次函数调用模拟“字节帧到达”，并把协议处理步骤显式打印出来。

## 示例输入与输出含义

程序构造的四元组是：

```text
客户端 192.0.2.10:51514 -> 服务端 198.51.100.20:80
TCP Seq=1001, Ack=7001, Flags=PSH|ACK
HTTP: GET / HTTP/1.1, Host: example.local
```

TCP 载荷是 58 字节。若发送端序号从 `1001` 开始，接收方确认这一段后，累计确认号应为 `1059`（`1001 + 58`），表示下一个期待的字节序号。这个值用于说明 TCP 按字节编号；程序示例展示的是发出方向报文中的 Ack 字段 `7001`，并没有模拟服务端返回 ACK。

运行日志中可以看到如下字段：IPv4 总长为 98 字节（20 字节 IPv4 头部 + 20 字节 TCP 头部 + 58 字节载荷），Ethernet 帧长为 112 字节（再加 14 字节 Ethernet 头部）。

```text
[L3 IPv4] 版本=4 头长=20 字节 总长=98 字节 TTL=64 协议号=6
  源 IP: 192.0.2.10  -> 目的 IP: 198.51.100.20
[L4 TCP] 源端口=51514 -> 目的端口=80
  Seq=1001 Ack=7001 头长=20 字节 窗口=64240
```

每一层通过上一层的类型/长度字段找到下一层：Ethernet 的 EtherType 指出 IPv4；IPv4 的 Protocol 指出 TCP；TCP 的数据偏移指出 HTTP 文本从哪里开始。长度检查保证解析器不会按报文里不可信的长度字段越过输入缓冲区。

## 字节序与校验和

网络协议的多字节整数使用大端序（高位字节先出现）。`read_be16`、`read_be32` 和对应写函数显式转换字节，避免依赖机器字节序或未对齐结构体访问。

IPv4 校验和覆盖 IPv4 头部；TCP 校验和覆盖 TCP 伪首部（源/目的 IP、协议号和 TCP 长度）及 TCP 头部与载荷。伪首部只参与校验和计算，不会作为额外字节发送。
